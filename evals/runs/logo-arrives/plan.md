# フラット PNG ロゴ（マーク＋2語、白背景）の扱い

入力はレイヤーではなく1枚のラスター。装飾用テクスチャとして各ショットに押し付けるものではない。動かすのは「名前ショット」での組み立てアニメーション用に切り出した部分だけ。完成形のロゴは「名前ショット」と「エンドカード」の2回だけ画面に出す。

---

## 1. 何を動かしてよいか（パーツの決め方）

**見て決める。** 機械的に全部バラすのではなく、すでに独立したシルエットとして読める塊だけをパーツにする。

| 階層 | 原則 |
| --- | --- |
| マーク vs 語 | マーク（シンボル）と語（2行または2語）は常に別グループ。語は通常1つのベースライン上のロックアップとして扱う。 |
| マークの内側 | フレーム、バー（ダッシュ）、バッジ（円）など、**もともと自分の輪郭を持つ形状**だけを切り出す。 |
| 切り出さない | 親パーツに独立したエッジがない領域は、親に残す。無理に細かく分けない。 |

**語（2語）について:** 2つのクロップは**同じ垂直原点・同じスケール**を共有する。語間の水平オフセットは定数（例: `PREFLIGHT_OFFSET`）としてコードに持ち、レンダー時に推測しない。そうしないとベースラインがずれる。

**アニメーションの役割（名前ショット）:** パーツごとに動きを付ける（例: フレームはスプリングで 0.6→1 スケール、バーは `clip-path` でワイプ、バッジはスプリング＋中心回転、語は overflow 隠しの行から上昇、2語目は1語目より数フレーム遅れ）。エンドカードでは**すでに組み立て済み**のロックアップを表示する。

**やらないこと:** フックやプリンシプル、商品ショットの余白を埋めるためにロゴを角にスタンプする、参照クリップの幾何学模様の代わりにロゴを繰り返す、など。レビューで「参照っぽい」と言われたらグラフィックを削り、長さは保つ。ロゴで穴を埋めない。

---

## 2. 領域の見つけ方（計測してから切る）

順序は **決める → 計測 → 切る**。白背景のため `cropdetect` は often 無意味なので、暗ピクセル集計が主手段。

### 2.1 マーク帯と語帯（行方向）

1. ロゴ PNG をグレースケールの raw に落とす（例: `ffmpeg -i logo.png -f rawvideo -pix_fmt gray logo.gray`）。
2. **行ごと**に暗ピクセル数を数える（numpy 等）。
3. 暗さが「静か」になる行境界で、**上帯＝マーク、下帯＝2語**を分ける（「マークの上、2語の下」というレイアウトの典型パターン）。

### 2.2 2語の左右（列方向）

同様に**列ごと**の暗ピクセル数で、語と語の間の静かな列を見つけて水平クロップする。ここで得た矩形は後述の「共通原点・共通スケール」の前提。

### 2.3 マーク内の幾何（グリッド）

マーク帯だけをクロップし、**グリッドを重ねて**読む:

- バッジの円の中心・半径
- バー（ダッシュ）の始端・終端（矩形）
- フレームの欠け（例: 右下にバッジが食い込むギャップ）→ 円マスクでバッジを持ち上げ、残りをフレーム用「remainder」マスクに

Preflight 実例では、マーク内の独立形状がフレーム・ダッシュ・円形バッジの3つだった。

### 2.4 マスクで切り出し（ffmpeg `geq`）

各パーツ用マスクを式で定義し、黒 RGB + 輝度からのアルファ × マスクで透明 PNG にする:

```
format=rgba,geq=r='0':g='0':b='0':a='clip((250-g(X,Y))*1.07,0,255)*MASK',crop=W:H:X:Y
```

マスクの典型:

- **円:** `lte(hypot(X-cx,Y-cy),r)`
- **矩形:** `between(X,x0,x1)*between(Y,y0,y1)`
- **残り:** `not(円)*not(矩形)`（マーク crop 内）

切り出しは `scripts/sync-assets.mjs` のような同期スクリプトにまとめ、`public/` にレイヤー PNG を置く。

## 3. 切り口の確認（カットチェック）

**白の上では確認しない。** 白背景ロゴは、フリンジや欠けたストロークが白に溶けて「問題ないように見える」。

手順:

1. 全レイヤーを**強い単色背景**（実例ではオレンジ）の上に合成する。
2. 各レイヤーを個別にも同背景で見る。
3. ハロー、ギザギザ、欠け、二重線、語のベースラインずれがないか目視する。

問題があればマスク境界・crop 矩形・語の共通スケール／オフセット定数を直し、再 export する。名前ショットに進む前にここで止める。

---

## 4. どのショットにロゴが出るか

ストーリー上、ブランドは**問題（フック）のあと**に一度名前として登場し、**最後にもう一度**締めくくる。ロゴの「組み立て」は1回だけ。

| ショット | ロゴ | 内容 |
| --- | --- | --- |
| **Hook** | なし | 登場人物（アクター）と共有の問い。ブランドより前。 |
| **Name / LogoReveal** | **あり（組み立て）** | 供給ロゴのパーツがアニメで集まり、その後タグライン。フィルム内でロゴが「組み立てられる」のはここだけ。 |
| **Proof / 2nd actor / Control 等** | なし | 実 UI とキャプチャ。ロゴで装飾しない。 |
| **Principles** | なし | 制約をタイプのみ。シェイプもロゴも付けない。 |
| **End card** | **あり（完成形）** | ロゴ（ assembled ）、レジストリ行、パッケージ名など。フェードアウト。 |

参照の beat map でも「相手のロゴロックアップ → 自プロダクトのエンドカード」に対応する。**Done when** チェックリスト: 「ロゴは1回組み立て、エンドカードで1回 assembled」。

ショット以外（配布後）: 同じマーク crop を正方形パディングしてアイコン、ロックアップを README ヘッダーに——これは Remotion の「ショット」ではなくリリース資産。

---

## 5. タイミングの目安（Worked example）

120 BPM・30fps・1 beat = 15 frames のグリッド上の一例（EmDash Preflight）:

- **LogoReveal:** 105 frames — 組み立て + タグライン
- **EndCard:** 150 frames — 完成ロゴ + 取得先 + フェード

ショット長を変えたら音声ベッドも再生成する。ロゴレイヤー自体は duration よりパーツのキーフレーム設計に依存する。

## 6. 短いチェックリスト

- [ ] 動かすパーツは「独立した形状」だけ；語は1ベースライン用に原点・スケール・水平オフセットを固定
- [ ] 行／列の暗ピクセル数で帯を取り、マーク上はグリッドで円・矩形・remainder を測った
- [ ] 強色背景で合成確認（白背景のみで合格にしない）
- [ ] 画面上的なロゴは **LogoReveal（組み立て）** と **EndCard（完成）** の2ショットのみ
